# 取数配方 · 家底快照助手

每条配方只说「**该调哪些视图**」。**不含任何公式** —— 折算、汇总、收益、对比、趋势
全部由服务端算，技能只负责取回来摆好。

入口统一 `python3 scripts/read.py <视图> [参数]`；加 `--json` 出机器可读结果。

## 视图速查

| 视图 | 参数 | 取什么 |
|---|---|---|
| `overview` | — | 首页概览：当前净资产、总资产、总负债、最近一期、账户数 |
| `trend` | `--metric net_worth\|total_assets\|total_liabilities` | 各期走势 |
| `breakdown` | `--dim account\|platform\|category\|currency\|tag` | 当前结构占比 |
| `compare` | `<早期>` `<晚期>` `--dim …` `--mode origin\|current` | 两期对比 |
| `returns` | `--snapshot <id\|日期>`（缺省最新） | 收益面板（含每个账户为什么不可用） |
| `returns-breakdown` | `--dim account\|platform\|category\|currency` | 收益按维度拆解（**无 `tag`**） |
| `returns-trend` | — | 收益随期次变化 |
| `accounts` | `--archived true\|false` `--q <关键词>` | 账户列表（缺省只看在用的） |
| `account` | `<id\|名称>` | 单个账户档案 + 历史 |
| `snapshots` | `--from` `--to` | 快照列表（服务端**时间倒序**） |
| `snapshot` | `<id\|日期>` `--view origin\|current` | 某期明细 |
| `catalog` | `<币种\|平台\|分类\|标签\|all>` | 基础资料字典 |
| `rates` | — | 当前默认汇率表 |
| `settings` | — | 设置（本位币、界面版本、数据模式） |
| `import-preview` | `--file <csv>` | 导入预览（只读，不落库） |

## 常见任务 → 调什么

| 使用者这么问 | 调这些 |
|---|---|
| 「我现在有多少钱？」 | `overview` |
| 「这个月涨了多少？」 | `returns`（本期）→ 要跨期就看 `compare <上期> <本期>` |
| 「净资产是怎么变的？」 | `trend --metric net_worth` |
| 「钱主要放在哪？」 | `breakdown --dim platform`（或 `category`/`account`） |
| 「外币占多少？」 | `breakdown --dim currency` |
| 「哪几个账户贡献最大？」 | `breakdown --dim account` |
| 「上期到本期哪些账户在涨/跌？」 | `compare <早期> <晚期> --dim account` |
| 「收益为什么是这个数？」 | `returns`（先看每个账户的可用状态）→ 再 `returns-breakdown --dim account` |
| 「某个账户现在多少 / 什么时候建的？」 | `accounts --q <关键词>` → `account <id\|名称>` |
| 「有几期盘点 / 都在什么时候？」 | `snapshots` |
| 「某一期都有什么？」 | `snapshot <id\|日期>` |
| 「当时是什么口径？」 | `snapshot <id> --view current`（对比保存时冻结的原口径） |
| 「有哪些平台 / 币种 / 分类 / 标签？」 | `catalog all` |
| 「现在的汇率是多少？」 | `rates` |
| 「这份 CSV 导进来会怎样？」 | `import-preview --file <csv>`（只读，不写） |

## 问句 → 图型（出图时看这张表）

出图**不是义务**。加 `--viz` 会拿到一份图规格（`viz` 字段），渲染交给宿主平台；
**拿不到就照 `viz_note` 的理由改用文本，不要自己拼图**。哪些视图出什么图，
`python3 scripts/vizspec.py --list` 可直接打印。

| 使用者这么问 | 图型 | 视图 | 口径 |
|---|---|---|---|
| 「有多少钱」 | KPI（净资产 / 总资产 / 总负债） | `overview` | server |
| 「按 X 看结构」 | 横向条形（净值降序，**不重排**） | `breakdown --dim X` | server |
| 「占比多少」 | 条形 + **派生占比序列**（加 `--share`） | `breakdown --dim X --share` | server + **derived** |
| 「这几个月怎么变的」 | 折线（≥3 期才画） | `trend` | server |
| 「和上期比 / 哪些在涨跌」 | 双向条形（`row.dir` 涨红跌绿） | `compare` | server |
| 「收益怎么样 / 谁拖后腿」 | 条形 + 状态标记 | `returns-breakdown` | server |
| 「收益趋势」 | 折线（≥3 期才画） | `returns-trend` | server |

**不出图（有理由，不是漏做）**：

| 情况 | 为什么 | 怎么办 |
|---|---|---|
| `accounts` / `account` / `snapshots` / `snapshot` / `catalog` / `rates` / `settings` / `import-preview` | 词典式清单或账目明细，出图反而丢细节；导入预览是**待确认清单**，出图会误导成「已生效」 | 直接给文本 |
| 条目 **> 12 项** | 条形会糊 | 退回表格或缩小范围（**不做降采样：降采样属于聚合**）。⚠ 只是否掉**图**：`--share` 要的占比仍会单独出现在 `share` 字段里（见下条）|
| 折线 **< 3 期** | 两期是「对比」不是「走势」 | 改用 `compare` |
| 服务端没有对应数字 | 图上出现自造数就会变成第二口径 | 如实说「服务端不提供」 |

## 判读纪律

- **列表顺序**：`/snapshots` 是**时间倒序**（最新在前）；`trend` 等走势类由服务端按时间升序给。
- **`prev_amount`（「较上一期」）不保证是列表里紧邻的那一期** —— 服务端挑的是
  「比本期更早、**且包含该账户**的最新一张」。所以**不要写出基准日期**，也**不要**说「上期」。
  且它只在 `status == 'ok'` 时才有值；未跟踪本金 / 首期 / 基准缺失时都是 `—`，副文案只写
  「无可用对比基准」，不猜原因。
- **收益五态**：`ok` / `not-tracked` / `no-principal` / `first` / `base-missing`。
  ⚠ `not-tracked`（没开本金跟踪）**不得**说成「未填本金」。
- **「首期」「基准缺失」只关闭本期收益，不关累计收益** —— 累计口径无条件算，照常给数。
- **同名账户不自动指认**：`account <名称>` 命中多个会报错并列候选，让使用者挑（用 id 或唯一名称）。
- **「查不到」是正常答案不是错误**：没有快照、没有这个日期，脚本给可读提示并 exit 0。
- **账户名与平台名是快照冻结时的名字**：设置里改过名，历史快照仍显示旧名 —— 这是设计如此。
  跨期对比一律用 **ID**，不要用名字。
- **金额展示**：技能只做「微元 → 元」的显示换算（接口契约的一部分），**不做任何口径计算**。
- **超范围分析**（服务端没算的，如归因拆解、最大回撤）必须带前缀
  「**非系统口径 · 未落库 · 不出现在系统界面**」。详见 `safety.md`。
- **占比是派生量**：服务端的结构返回里**没有占比字段**，占比一定是技能算的。
  **默认不给**；使用者明确问「占比 / 比例 / 百分比」时，加 `--share` 取派生序列 ——
  它自带分母与标注，**图与文字都要把标注带上**。别把占比和净值混进同一条序列。
  ⚠ **占比不跟着图一起被否掉**：图的条目上限只保护可读性，占比是数据。
  `read.py breakdown account --share` 在 13 个账户时**依然要给得出占比**（用表格呈现），
  「画不下」不能变成「答不上来」。`--share` 也可脱离 `--viz` 单独使用。
- **图上的数字不许自造**：条形从 0 起；折线不从 0 起要在图上写出来；
  「收益不可用」画 `null`（**不画成 0**）；本位币变更点折线断开。
