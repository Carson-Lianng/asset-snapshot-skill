# 使用手册章节索引 · 家底快照助手

答疑（「这个功能怎么用」「系统里的某处是什么意思」）**只从账本包内的使用手册取正文**。
手册源码在账本包内的 `app/web/src/features/help/`（`outline.ts` 出章节骨架、`content.tsx` 出正文块），
由 `scripts/help.py` 结构化抽取。

用法：

```
python3 scripts/help.py list              # 列章节 + 抽取状态（✓/✗）
python3 scripts/help.py <章节id>          # 抽某一章正文，如 help.py concepts
python3 scripts/help.py <关键词>          # 按关键词找章节，如 help.py 备份
python3 scripts/help.py <关键词> --source # 附带正文来源路径
```

## 抽取的稳定性（三层，刻意**不做正文缓存**）

1. **打包硬校验**：`pack-release.mjs` 校验「手册必须在交付包内」，
   否则打包直接失败 —— 根治「旧包里根本没有手册源码」。
2. **结构化抽取**：`help.py` **只依赖结构契约**（`outline.ts` 的章节 id/标题 + `content.tsx` 的正文块），
   不做正则猜格式。
3. **失败显式降级**：抽不到就 `exit 3` 并说明原因（「这个账本包里没有使用手册源码」），
   **不猜、不编、不用模型补写**。

> 裁决理由：缓存不解决根因（旧包内本来就没有手册源码），且会在手册改版后形成
> 「过期却看似权威」的第二份文本。详见 `MEMORY-ops.md` 的设计定稿一节。

## 契约变了怎么办

手册改动**不破坏**抽取契约的三条红线：

- 章节 id 与标题写在 `HELP_OUTLINE` 的**数据字面量数组**里（不写成 JSX）。
- 正文按 **id → 正文常量** 的映射组织（`BODIES`）。
- 列表型正文由 `Xxx.map(...)` 渲染元组数组或含 `q`/`a` 的对象数组。

⚠ **手册正文是对「当前界面」的承诺**：界面改了必须**同批**改手册正文，
否则答疑会把使用者引向不存在的功能（项目里有两条守门断言钉住这类措辞）。

⚠ 手册**不是**「账号/数据」类问题的答案来源：涉及**这一本账本的具体数字**一律走 `read.py`，
手册只回答「这个系统怎么用」。
