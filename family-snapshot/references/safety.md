# 写操作安全分级 · 家底快照助手

**唯一实现是 `scripts/safety.py`。** 本文件是给人读的说明；分级表、硬禁止清单、
自查（`safety.py audit`）都在代码里。改分级要改代码，别只改这里。

## 三档

| 档 | 判定依据 | 门槛 | 错了怎么办 |
|---|---|---|---|
| **只读** | 不改变账本任何状态 | 无 | — |
| **可逆写** | 错了能改回来（能改、能归档、能丢草稿、能删快照、能随手备份） | `--confirm`（一次确认） | 使用者自己改回来 |
| **不可逆 / 影响全库** | 删了回不来，或影响之后所有折算 | **默认拒绝**；要 `--confirm` + `--confirm-2` | **脚本在动作前自动备份一次**；备份失败则拒绝执行 |

门禁在**连服务之前**执行 —— 缺确认参数时连账本都不会去连。

## 只读动作（直通）

问数、洞察、答疑、查看账户与字典、盘点试算、导入预览。

## 可逆写（9 个）

| 动作 | 接口 | 说明 |
|---|---|---|
| `account-create` | `POST /api/accounts` | 新建账户 |
| `account-update` | `PATCH /api/accounts/{id}` | 编辑账户档案 |
| `account-archive` | `PATCH /api/accounts/{id}` | 归档 / 恢复账户（历史快照不受影响） |
| `catalog-create` | `POST /api/{kind}` | 新建字典项（币种 / 平台 / 分类 / 标签） |
| `catalog-update` | `PATCH /api/{kind}/{ref}` | 编辑或停用字典项 |
| `draft-save` | `PUT /api/inventory/draft` | 保存盘点草稿（带真实版本号，冲突即报错） |
| `draft-discard` | `DELETE /api/inventory/draft` | 丢弃盘点草稿 |
| `snapshot-save` | `POST /api/inventory/snapshots` | 保存快照（须先出将写入清单并确认；保存后只能删不能改） |
| `backup-now` | `POST /api/backup` | 立即备份一次 |

## 不可逆 / 影响全库（7 个）

| 动作 | 接口 | 说明 |
|---|---|---|
| `account-delete` | `DELETE /api/accounts/{id}` | 删除账户（历史明细保留，账户本身没了） |
| `catalog-delete` | `DELETE /api/{kind}/{ref}` | 删除字典项（被引用时服务端 409 拒绝） |
| `snapshot-delete` | `DELETE /api/snapshots/{id}` | 删除一期快照（含明细与冻结汇率，不可撤销） |
| `base-currency-change` | `POST /api/settings/base-currency` | 变更本位币（整表反算汇率 + 写变更历史） |
| `rates-set` | `PUT /api/rates` | 整表覆盖默认汇率（不改历史快照，但影响之后所有折算） |
| `import-apply` | `POST /api/import/apply` | 应用导入（批量改账户档案；有冲突则整体拒绝） |
| `restore` | `POST /api/restore` | 从备份恢复（覆盖当前账本；服务端另留一份恢复前备份） |

## 硬禁止清单（6 条，不提供任何绕过路径）

1. **读写账本数据库文件**（含预写日志与共享内存文件）。
   *为什么*：直连会同时绕过微元换算、快照口径冻结、引用存在性校验与保存后自动备份 —— 最容易把真实账本改坏的路径。
2. **改账本的环境配置、迁移文件与包内脚本清单**。
   *为什么*：环境配置决定端口、数据目录与汇率源；改了会改变服务行为，而使用者无从得知。
3. **删账本数据目录、备份目录及其中的任何文件**。
   *为什么*：那就是账本本身。技能里没有任何删除文件的代码路径。
4. **调用账本自带的重置账本、灌演示数据、执行迁移命令**。
   *为什么*：重置会清空真实账本且不可逆；这些命令刻意要求使用者在终端亲手执行。
5. **把访问令牌写进地址、日志、导出物或任何对话输出**。
   *为什么*：令牌等于账本的钥匙；一旦外泄，本机任何进程都能读写账本。
6. **监听端口、修改服务端代码、代起常驻服务**。
   *为什么*：本项目出过「工具起的长驻进程跨会话存活、使用者重启撞端口失败」的故障。

`scripts/safety.py audit` 会自查技能自身不含被禁能力（危险模块、删除文件的调用、账本数据库访问），
输出 `✓ 0 违规` 才算通过。**改动任何脚本后都要重跑一次。**

## 刻意不提供的能力（4 项）

| 不提供 | 原因 |
|---|---|
| 清空账本 / 灌演示数据 | 账本自带的重置与演示数据命令（含界面上的「开始正式记账」端点）。清空真实账本不可逆，必须由使用者在终端亲手执行 |
| 执行数据库迁移 | 迁移属于账本自身的启动流程，改数据格式不在技能职责内 |
| 从外部汇率源刷新汇率 | 会让之后所有折算的基准发生变化，属使用者的自主决定；技能只在将写入清单里如实展示当前汇率 |
| 写入任意设置项 | 设置里含机制性键（数据模式、初始化标记、本位币、数据格式版本），服务端刻意挡住了一部分；技能不开这个口子 |

## 向使用者确认的标准话术

**录入前（第 2 步，必做）**：
> 请确认两点：① 每个账户填的是**当前实际价值**（不是买入成本）；② 负债填**正数**（系统自己算净值时做减法）。
> 另外确认盘点日期：默认今天（`YYYY-MM-DD`）。

**展示将写入清单后（第 4→5 步，必做）**：
> 以上是这次要写进去的全部内容（账户 / 原币金额 / 本金）。合计由系统试算，我不做本地折算。
> 有 **N 个账户本次未填写** —— 它们不会写进这一期，**不等于余额为 0**。确认要这样保存吗？

得到确认后才执行 `write.py`，并把脚本打印的完整命令原样交给使用者。

**缺确认参数时（exit 4）**：脚本会打印一行**可直接复制重跑的命令**。
把那一行原样交给使用者确认 —— **不要自己替使用者加上 `--confirm`**。

**语义提醒**：`--confirm` / `--confirm-2` 是使用者的确认凭证，不是脚本的内部开关。
缺参数意味着「使用者还没说要写」，正确动作是**去问**，不是补参数。

## 超范围分析的标注形态（设计文档 §八 开放问题 4 · 定稿）

技能允许在**服务端返回的数之外**做进一步分析（归因拆解、最大回撤、简单加减对比等），
但这类结果**必须**在输出里带一句固定前缀：

> **非系统口径 · 未落库 · 不出现在系统界面**

裁决：**只做统一文本前缀，不做结构化字段。**

理由：
1. 技能**不产出**任何有系统出处的数字；给它加结构化字段（如 `"provenance": "derived"`）
   会暗示「这是系统口径的一种」，恰好是这句前缀要否掉的事。
2. 没有任何机器消费者 —— 前缀是给**人**看的免责声明，加字段只增加被误用的面。
3. 固定措辞便于在探针里做**字符串断言**（`verify:family-snapshot` 已钉）。

反向约束：**服务端能算出来的东西，一律不得由技能本地算**。
「服务端算得出但技能自己算了一个不同的数」是硬错误，不是超范围分析。

### 出图时的标注（与上面这条裁决的关系）

问数出图（`references/recipes.md` 的「问句 → 图型」）时，派生量的标注在机器层面
多带三个字段：`caliber: "derived"`、`notice`（就是上面那句固定串）、`denominator`（分母是谁、值多少）。

**这不是开倒车**，两者职责不同：

| | 文本前缀 | `caliber` / `notice` / `denominator` |
|---|---|---|
| 给谁看 | **人** | **渲染层** |
| 解决什么 | 免责声明 | **让渲染层不可能漏标** —— 图会离开原文单独流转，只靠「调用方记得写」迟早漏 |
| 能否替代对方 | — | **不能**：它不得被当成「数字的出处声明」，也**不得**在最终输出里替代那句前缀 |

也就是说：字段是**保证前缀一定被写出来**的机制，最终呈现给人的仍然是那句中文前缀。
凡图上有 `caliber="derived"` 的序列，图上与文字里都必须出现
「非系统口径 · 未落库 · 不出现在系统界面」并写明分母。

**技能里唯一允许的算术是占比**（`scripts/vizspec.py` 的 `share_of()`，单点实现）——
因为服务端的结构返回里没有占比字段。除此之外技能不产生任何数字。
