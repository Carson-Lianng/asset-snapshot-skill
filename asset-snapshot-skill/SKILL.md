# 家底快照助手

把「家底快照」账本系统（本机单端口服务）包装成面向任务的操作入口：**录入 / 洞察 / 问数 / 答疑**。
技能只与本机 HTTP 接口对话，不碰账本数据库文件。

## 硬性规则（违反即错，不得绕过）

1. **只走 HTTP 接口**：读写一律经 `scripts/` 里的脚本，脚本只调本机 `/api/*`。
   不直连、不读写账本数据库文件（含预写日志与共享内存文件）——直连会同时绕过单位换算、
   快照口径冻结、引用校验与自动备份。
2. **口径只有一个来源：服务端**。折算、汇总、收益、两期对比、趋势，**一律取服务端返回的数**；
   技能内不含任何口径实现，也不缓存口径结果。技能只做两件事：调接口、把结果摆给人看。
   金额单位换算（元 ↔ 微元）是接口契约的一部分，只在 `scripts/_common.py` 一处完成，与口径无关。
3. **写操作必须过安全分级**（见 `references/safety.md`，唯一实现是 `scripts/safety.py`）：
   只读直通；可逆写要 `--confirm`；不可逆或影响全库的写**默认拒绝**，要 `--confirm --confirm-2`
   且脚本在动作前自动备份一次。
4. **不猜、不编**：服务端报错就原样把 `code` 与 `message` 摆出来；手册没写就说是没写；
   接口取不到数就说取不到。任何超范围分析（归因拆解、最大回撤等）必须标注
   「非系统口径 · 未落库 · 不出现在系统界面」。
5. **不代起服务**：服务没跑就提示并给出启动命令，由使用者自己启动（避免长驻孤儿进程占端口）。
6. **不向使用者索要、也不输出访问令牌**；令牌只从数据目录的令牌文件读取，不进日志、不进导出物。
7. **图即口径呈现**（问数出图时适用，唯一实现是 `scripts/vizspec.py`）：
   - **V1** 图上每个数字都必须能在接口返回里指到同名字段；技能**不排序、不聚合、不补零**。
   - **V2** `caliber` 是**序列级必填**（`server` / `derived`）—— 一张图里混着两种来源也能逐条标清。
   - **V3** `derived`（派生量）必须带 `formula_text`、`denominator`（写明分母是什么、值多少）
     与固定标注串「**非系统口径 · 未落库 · 不出现在系统界面**」。**默认不出派生量**：
     只有使用者明确问「占比 / 比例 / 百分比」时才加 `--share`。**唯一允许的算术是占比。** 且**占比不跟着图一起被否掉** —— 图的条目上限只保护可读性，
图出不来时 `share` 必须仍然可取，改用表格呈现（不让「画不下」变成「答不上来」）。
   - **V4** 图**只进对话**（`--json --viz` 取规格由宿主渲染），**不落文件**——不产出可脱离来源流转的副本。
   - **V5** 特征态不许被图掩盖：收益不可用画 `null`（**不画成 0**）；折算参考值要标；
     本位币变更点折线**断开**；收益「不可用」的行留空。
   - **V6** 颜色只给**语义角色**（`up` / `down` / `sign` / `neutral` / `derived`），
     由渲染层按主题落地：**涨红跌绿**（中国市场口径，与系统界面一致）。
   - **V7** 条形必须从 0 起；折线不从 0 起时必须在图上标注。
   - 出图是**加分项不是义务**：`read.py … --viz` 若返回 `viz_note`，就**照它的理由改用文本**，
     不要绕过它自己拼图；`vizspec.py --list` 可打印哪些视图出图、哪些不出、为什么。

## 五步工作流

| 步骤 | 做什么 | 脚本 | 门槛 |
|---|---|---|---|
| 1 定位与自检 | 找到账本、确认服务在跑、令牌可读、数据模式、手册是否可用 | `doctor.py` | **自检不通过不得进入任何写流程** |
| 2 理解意图选路 | 判断走「录入 / 问数 / 洞察 / 答疑」；录入先与使用者确认口径（填**当前实际价值**、负债填**正数**）与盘点日期 | — | 录入前必须确认口径与日期 |
| 3 取数 | 问数与洞察一律由服务端出数；能让图说清的（结构 / 趋势 / 对比）加 `--viz` 取图规格，由宿主平台渲染，无渲染能力时退回 Markdown 表、再退回文本 | `read.py` | 数字只能来自服务端；**取不到 `viz` 就照 `viz_note` 的理由用文本，不自己拼图** |
| 4 录入编排 | 录入项 → 匹配账户 → 服务端权威试算 → **将写入清单** | `plan.py` | **清单必须完整展示给使用者并得到确认** |
| 5 落库 | 按安全分级执行，回执里回显目标账本 | `write.py` | 无确认参数一律拒写 |
| 答疑 | 抽取账本包内的使用手册正文作答 | `help.py` | 手册没覆盖就如实说明，不编造 |

## 脚本速查

所有脚本只用 Python 标准库；入口统一 `python3 <脚本>`；公共参数：

| 参数 | 作用 |
|---|---|
| `--ledger <路径>` | 显式指定账本根目录（压过配置与环境变量） |
| `--base-url <URL>` | 显式指定服务地址，如 `http://127.0.0.1:5188` |
| `--json` | 机器可读输出（紧凑 JSON）；缺省是人读摘要 |
| `--viz` | 随返回体附**可视化规格**（`viz` 字段；不出图时给 `viz_note` 说明理由）。规格是给宿主渲染的，技能不画图 |
| `--share` | 追加**派生**占比 —— 服务端不提供占比；会自带固定标注与分母。仅 `breakdown` / `compare` / `returns-breakdown` 支持，其它视图**显式报错**（不静默忽略）；**只在使用者明确问占比时才加**。⚠ 与 `--viz` **解耦**：占比是数据，图的条目上限只管可读性，所以不带 `--viz` 也能单独取占比；图因条目过多被否掉时 `share` 照样在 |

| 脚本 | 用法 | 做什么 |
|---|---|---|
| `scripts/doctor.py` | `doctor.py [--remember]` | 账本定位 + 环境自检（服务 / 令牌 / 版本 / 数据模式 / 手册可用性） |
| `scripts/read.py` | `read.py <视图> [参数]` | 只读取数，见下表 |
| `scripts/plan.py` | `plan.py --date YYYY-MM-DD --items <文件\|-> [--note 备注] [--out 文件]` | 录入项 → 服务端试算 → 将写入清单 |
| `scripts/write.py` | `write.py <动作> [参数] [--confirm] [--confirm-2]` | 全部写操作，见 `references/safety.md` |
| `scripts/safety.py` | `safety.py list [--action 动作]` / `safety.py audit` | 打印分级表与硬禁止清单 / 自查技能自身不含被禁能力 |
| `scripts/help.py` | `help.py list` / `help.py <章节id\|关键词>` | 定位并抽取账本包内的使用手册正文 |
| `scripts/vizspec.py` | `vizspec.py --list` / `vizspec.py --view <视图>` | 打印「哪些视图出什么图、哪些不出、为什么」；**它只做字段映射，不画图、不算口径**（唯一例外是占比，见硬规则 V3） |

`read.py` 视图：`overview` · `trend` · `breakdown <维度>` · `compare <早期> <晚期>` ·
`returns` · `returns-breakdown <维度>` · `returns-trend` · `accounts` · `account <id\|名称>` ·
`snapshots` · `snapshot <id\|日期>` · `catalog <币种\|平台\|分类\|标签\|all>` · `rates` · `settings` ·
`import-preview --file <csv>`

维度取值：`account` / `platform` / `category` / `currency` / `tag`（收益维度不含 `tag`）。

## 退出码

| 码 | 含义 | 该怎么做 |
|---|---|---|
| 0 | 成功 | — |
| 2 | 服务端拒绝了这次请求（含业务规则） | 把 `code` 与 `message` 原样告诉使用者，不要自行改写规则 |
| 3 | 手册不可用或章节不存在 | 按脚本提示降级（升级包版本 / 打开界面手册对应章节） |
| 4 | 写操作缺少确认参数 | 把脚本打印的「补上确认后的完整命令」交给使用者确认，不要自己加上 |
| 10 | 服务不可达 | 提示启动命令，不代起 |
| 11 | 定位不到账本 | 列候选给使用者挑，或让使用者用 `--ledger` 指定 |
| 12 | 令牌文件读不到 | 提示账本数据目录与令牌文件路径 |

## 账本定位

三级定位，先命中者为准：`--ledger` / 环境变量 `ASSET_SNAPSHOT_SKILL_LEDGER` →
记住的配置（`~/.asset-snapshot-skill/config.json`，`--remember` 写入）→ 从当前目录向上搜索
含 `.data/` 的目录。服务地址同理（`--base-url` → 配置 → 账本 `.env` 的 `PORT` → 5188）。

## 安装

把 `asset-snapshot-skill/` 整个目录拷进目标平台的技能目录。WorkBuddy 用户级为 `~/.workbuddy/skills/`：

```bash
cp -R agent/asset-snapshot-skill ~/.workbuddy/skills/
```

- **拷贝前后都不要带 `__pycache__/`**（Python 自动生成，平台无关，不必分发）。
- ⚠⚠ **改了 `agent/asset-snapshot-skill/` 里的源码后，必须重新拷一次**（副本不会自动跟着变）。
  2026-10-06 就栽过一次：仓库归位后源码已改成 `app/web/src/features/help`，装机副本还停在
  归位前的写法（顶层那一级还是复数形式）⇒ `doctor.py` 报「手册不可用」、`help.py` 必然失败，
  **症状离根因极远**。
  用 `npm run check:skill:refs` 可以查出来（它会比对两份是否还一致）。
- 装完**新开一个会话**让平台重新加载技能列表，再跑一次 `doctor.py` 自检。
- 可选的平台标记：若目标平台用某个字段登记「这条技能是助手创建的」（WorkBuddy 是
  frontmatter 的 `agent_created: true`），**装完之后**在技能副本的 frontmatter 里补上即可。
  本目录是交付物，**刻意不带任何平台特有字段**（设计 §2），所以标记只加在装机副本上。
